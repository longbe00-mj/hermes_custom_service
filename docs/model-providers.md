# 중앙 모델 프로바이더 관리

## 구현 범위

관리자 포털의 **모델 프로바이더 관리**에서 OpenAI와 Anthropic을 설정한다.
현재 연결 방식은 공급자 API 키다. OAuth 연결 기능은 활성화하지 않았다.

1. 프로바이더를 선택하고 API 키, 허용 모델 ID, 전체 기본 모델 ID를 입력한다.
2. 사용자에게 활성화를 선택하고 저장한다. 키를 비워 두면 기존 키가 유지된다.
3. 저장된 키로 연결 확인 / 모델 조회를 누르면 공식 `/v1/models`를 조회한다.
   조회 성공은 인증과 모델 목록 접근 확인이며, 실제 생성·도구 호출 검증은 아니다.
4. 사용자 포털에서 허용 모델을 선택한다. 기존 개인 환경은 중지 후 시작하고 새 세션을 연다.

모델 ID는 관리자 소유 계정에 실제 허용된 ID를 사용한다. 예시 ID를 자동 활성화하지 않는다.
Anthropic 다중 워크스페이스 키는 필요에 따라 Workspace ID를 추가한다.

## 요청 경로와 제한

- 사용자 런타임의 main 모델은 `custom`, 중앙 `/v1`, `central-default` 별칭을 사용한다.
- `central-default`는 사용자 선택 모델로 해석한다. 선택 모델이 제거되면 중앙 기본 모델로 돌아간다.
- 실제 모델 ID로 요청해도 매 요청마다 활성 공급자의 허용 목록을 검증한다.
- 비활성화한 공급자 및 미허용 모델은 upstream 요청과 사용량 예약 전에 거부한다.
- `/v1/models`와 `/platform/api/models`는 같은 허용 목록을 읽는다.
- 모델 선택은 다음 요청에 적용된다. 이미 진행 중인 응답은 변경하지 않는다.
- 새 기본 정책은 기존 대화 기록이나 프롬프트를 재작성하지 않는다.
- 기존 실행 중 컨테이너는 자동 재시작하지 않는다. 명시적 중지·시작 시 새 런타임 이미지로 교체하며
  기존 사용자 데이터 볼륨은 보존한다. 설정 반영 후에는 새 세션을 연다.

주 API는 Chat Completions다. Anthropic은 공식 OpenAI SDK 호환 계층으로 연결한다.
텍스트, 도구 호출, SSE 및 사용량을 전달하지만, native Messages의 전체 기능·프롬프트 캐싱·thinking
동작을 동일하게 제공한다고 보장하지 않는다. 운영 검증 시 실제 공급자의 기능 제한을 확인한다.

중앙에서 제공하는 모델 호출에 대한 접근 제어다. Hermes 사용자에게는 임의 명령·브라우저 실행 능력이
있으므로 사용자가 자신의 자격증명으로 외부 서비스를 직접 사용하는 것까지 막는 샌드박스는 아니다.
그 수준의 차단에는 도메인 허용 목록과 별도의 실행 정책이 필요하다.

## 자격증명과 권한

- 프로바이더 키는 `app_key`에서 도메인 분리해 유도한 키와 Fernet으로 인증 암호화한다.
- `model_providers`에는 암호문만 저장한다. 조회 API·감사 기록에는 키를 반환하지 않는다.
- 저장·연결 테스트는 active, 이메일 확인 완료 관리자만 가능하다. 쿠키 요청에는 기존 CSRF 정책을 적용한다.
- 개인 런타임은 자체 범위의 런타임 토큰만 받으며 원본 공급자 키나 암호화 키를 받지 않는다.
- 공급자 호스트는 서버 상수로 고정한다. 사용자가 임의 base URL을 지정할 수 없다.
- 기존 런타임의 OAuth/프로바이더 관리 경로는 중앙 프록시에서 차단한다.
- API 키 교체는 저장 즉시 새 요청에 적용한다. 연결 비활성화는 키를 삭제하지 않는다.
- 최초 업그레이드에는 기존 `config.yaml` 모델 목록과 `provider_api_key`를 보존한다.
  관리자 설정을 저장한 후에는 DB 정책이 우선한다. 기존 파일 키를 폐기하려면 운영자가 secret 파일도 비운다.
- 백업의 DB 덤프에는 암호문, secret 백업에는 복호화에 필요한 `app_key`가 포함되므로 함께 보호한다.
  `app_key`를 임의 교체하면 기존 키를 읽을 수 없다. 키 재등록 또는 별도 재암호화 이관이 필요하다.

## OAuth 기능 검토 — 2026-10-20

원본 Hermes는 ChatGPT/Codex 및 Anthropic OAuth 기능을 갖고 있으나, 해당 개인 프로필 연결을
중앙 다중 사용자 서비스에 그대로 복제하는 것은 별도 문제다.

- OpenAI의 [ChatGPT plan usage](https://developers.openai.com/siwc/token-sharing-open-source)는
  사용자와 선택한 워크스페이스 단위 클라이언트·호스트를 설명한다. 원격 호스팅 또는 유료 앱은
  별도 문의 대상으로 안내되어 있다. 관리자 개인 토큰을 전체 사용자에게 공유하는 지원 계약은 확인되지 않았다.
- Anthropic의 [개발자 안내](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)는
  다른 사용자를 위한 제품·서비스에 API 키 또는 지원 클라우드 공급자를 사용하도록 안내한다.
- 따라서 이 서비스의 관리자 화면에는 OAuth 미지원 이유와 공식 안내 링크를 표시한다.
  작동하지 않는 로그인 버튼, 구독 토큰 가져오기, Claude Code 위장 헤더는 제공하지 않는다.
- 승인된 OAuth 클라이언트·이용 범위가 확보되면 별도 통합한다. 사용자 귀속 연결인지 조직 공유 grant인지
  먼저 확인하고, PKCE/state, callback 등록, 서버 암호화 저장, refresh 단일 소비 잠금, 해제·만료 처리,
  권한 범위와 실제 inference 프로토콜 검증을 추가해야 한다.

Anthropic 호환 계층: [공식 문서](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk).

## 검증 구분

계약 테스트는 실제 임시 PostgreSQL DB와 ASGI를 사용한다. 공급자 응답만 mock으로 대체하여
관리자 권한, 키 보존·암호화·비노출, 연결 테스트, 목록/선택/호출의 허용 모델 제한,
공급자 비활성화, Anthropic 호스트·헤더·도구 전달·사용량 정산을 확인한다.
실제 공급자 자격증명이 없으므로 실제 OAuth 동의, 유료 모델 응답, 공급자별 tool 실행은 미검증이다.

## Hermes GUI Models 메뉴 연동 (2026-10-21)

GUI의 `/api/model/options`와 WebSocket `model.options`는 런타임 공급자 inventory 대신 중앙 정책을 반환한다. include_unconfigured, refresh, profile 파라미터로 외부 공급자나 미설정 모델을 추가할 수 없다. 키 등록·활성화·허용 목록 조건을 모두 만족한 모델만 Central 공급자 그룹에 표시한다. 연결 모델이 없으면 빈 목록을 반환한다.

GUI main 모델 저장은 중앙 사용자 모델 선택으로 처리한다. 임의 공급자, endpoint, key, 보조 모델 override는 허용하지 않는다. GUI의 main 상태는 중앙 선택 모델을 표시하며 보조 모델 개별 설정 컨트롤은 노출하지 않는다. 이 UI 응답은 기존 런타임의 보조 설정 파일을 삭제하거나 변경하지 않는다. 실행 중인 세션 변경 조건은 앞의 요청 경로와 제한 절을 따른다.
